## Overview

A command-line process multiplexer, CPU scheduler, and **memory manager** emulator written in C++17. Builds on MO1's scheduler by adding per-process memory allocation, demand paging, and memory-related instructions and reporting.

The system emulates a simplified OS shell with:

- A **CLI console** recognizing OS-level commands
- A **screen multiplexer** (inspired by Linux `screen`), now with `screen -c` for pre-loaded instruction strings
- A **CPU scheduler** supporting FCFS and Round-Robin, now memory-gated (a process only gets a core once it has memory)
- **Process instructions** via the ICommand pattern: `PRINT`, `DECLARE`, `ADD`, `SUBTRACT`, `SLEEP`, `FOR`, and the new **`READ`** / **`WRITE`** memory instructions
- A **SymbolTable** for per-process variable storage
- Two interchangeable **memory allocators** behind a common `IMemoryAllocator` interface:
  - `FlatMemoryAllocator` — contiguous best-fit allocation with external fragmentation tracking
  - `PagingAllocator` — fixed-size frames, per-process page tables, and **FIFO demand paging**
- A **BackingStore** (`csopesy-backing-store.txt`) that pages evicted frames out to disk and back
- Memory-aware reporting via **`process-smi`** and **`vmstat`**
- A **config.txt**-driven setup (no recompilation needed to change parameters)

### Design References
- **MO2 Specs** (`MO2 - OS Emulator - Multitasking OS.docx`) — Feature requirements and assessment criteria (paging, backing store, memory violations, `process-smi`/`vmstat` formats)
- **MO1 Specs / Midterm Review** — Scheduler, ICommand pattern, SymbolTable, PCB design carried over from MO1

## Build & Run

### Prerequisites
- C++17 compatible compiler (g++ / MSVC / clang++)
- POSIX threads (`-pthread` on Linux/MinGW)

### Compile (g++)
```bash
g++ -std=c++17 -Wall -pthread -o csopesy *.cpp
```
All `.cpp` files are in the repo root, so `*.cpp` picks up everything — no separate file list to maintain as files are added.

### Run
```bash
./csopesy
```

### First Command
```
> initialize
```
This reads `config.txt`, builds the scheduler, and constructs the active memory allocator (`PagingAllocator`, using `mem-per-frame`/`max-overall-mem`). No other commands work until this is run.

## config.txt Format

Space-separated key-value pairs. Example:

```
num-cpu 4
scheduler "fcfs"
quantum-cycles 5
batch-process-freq 1
min-ins 1000
max-ins 2000
delay-per-exec 0
max-overall-mem 16384
mem-per-frame 16
min-mem-per-proc 64
max-mem-per-proc 4096
```

| Parameter            | Description                                          | Range         |
|-----------------------|-------------------------------------------------------|---------------|
| `num-cpu`             | Number of CPU cores                                   | [1, 128]      |
| `scheduler`           | Scheduling algorithm: `"fcfs"` or `"rr"`               | —             |
| `quantum-cycles`      | Time slice for Round-Robin (ignored by FCFS)           | [1, 2³²]      |
| `batch-process-freq`  | New process every X CPU cycles                         | [1, 2³²]      |
| `min-ins`             | Minimum instructions per process                       | [1, 2³²]      |
| `max-ins`             | Maximum instructions per process                       | [1, 2³²]      |
| `delay-per-exec`      | Busy-wait delay ticks between instructions              | [0, 2³²]      |
| `max-overall-mem`     | Total simulated physical memory, in bytes (**NEW**)     | —             |
| `mem-per-frame`       | Bytes per page/frame (**NEW**)                          | —             |
| `min-mem-per-proc`    | Minimum memory a process can request (**NEW**)          | power of 2, [64, 65536] |
| `max-mem-per-proc`    | Maximum memory a process can request (**NEW**)          | power of 2, [64, 65536] |

## Commands

| Command                              | Context    | Description                                                        |
|---------------------------------------|-----------|----------------------------------------------------------------------|
| `initialize`                          | Main menu | Load config.txt, boot scheduler + memory allocator                   |
| `screen -s <name> <mem>`              | Main menu | Create a new process with the given memory size and enter its screen |
| `screen -c <name> [mem] "<instrs>"`   | Main menu | Create a process with explicit instructions (**NEW**, MO2)           |
| `screen -r <name>`                    | Main menu | Reattach to an existing process screen; shows violation info if `TERMINATED` |
| `screen -ls`                          | Main menu | List all processes, CPU utilization, memory usage/fragmentation      |
| `scheduler-start` / `scheduler-test`  | Main menu | Begin batch process generation (aliases for the same behavior)       |
| `scheduler-stop`                      | Main menu | Stop batch process generation                                        |
| `process-smi`                         | Main menu | High-level memory + CPU summary, `nvidia-smi`-style (**NEW**)        |
| `vmstat`                              | Main menu | Detailed memory, CPU tick, and paging stats (**NEW**)                |
| `report-util`                         | Main menu | Generate CPU + memory utilization report → csopesy-log.txt           |
| `clear`                               | Main menu | Clear the console                                                    |
| `exit`                                | Both      | Exit screen → main menu, or quit application                        |

### New instructions (inside `screen -c "..."` instruction strings)
| Instruction              | Description                                                                 |
|---------------------------|-----------------------------------------------------------------------------|
| `READ varName 0xADDR`     | Reads a `uint16` from the process's memory into a symbol-table variable. Terminates the process on an out-of-range address. |
| `WRITE 0xADDR value|var`  | Writes a `uint16` (literal or variable) to the process's memory. Terminates the process on an out-of-range address. |

## Memory Management Summary

- Every process is assigned a memory size at creation (`screen -s`/`screen -c`), enforced to be a power of 2 in `[min-mem-per-proc, max-mem-per-proc]`.
- The active allocator is `PagingAllocator`: physical memory is divided into fixed `mem-per-frame`-byte frames; each process gets a page table mapping virtual pages to physical frames.
- A process only gets assigned to an idle core once `IMemoryAllocator::allocateForProcess()` succeeds — if there isn't enough memory (and eviction still can't make room, or the process's own requirement exceeds total system memory), it's requeued instead of run.
- **Demand paging**: `READ`/`WRITE` instructions trigger `ensurePageLoaded()`, which page-faults in the needed page — evicting the oldest resident page (FIFO) to the `BackingStore` if RAM is full, then loading the requested page back in.
- **Access violations**: an out-of-range address (or an address that can't be resolved) calls `Process::terminateWithViolation()`, which records the invalid address and an HH:MM:SS timestamp and moves the process to `TERMINATED`. `screen -r <name>` reports this instead of the normal output log.
- `process-smi` and `vmstat` both read live stats from the active `IMemoryAllocator` and the `Scheduler`'s CPU tick counters — no separate bookkeeping to keep in sync.

### Design Patterns Used

| Pattern                     | Where                                      |
|-------------------------------|---------------------------------------------|
| **Command Pattern**            | `ICommand` + concrete commands (incl. `READ`/`WRITE`) |
| **PCB (Process Control Block)**| `Process` class                              |
| **Symbol Table**                | `SymbolTable` class                          |
| **Strategy / Interface**        | `IMemoryAllocator` — swappable Flat vs Paging allocators |
| **Thread Workers**              | `Scheduler` core worker threads              |
| **Single Ready Queue**          | `Scheduler` — memory-gated dequeue           |
